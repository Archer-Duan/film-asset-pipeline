# 数字资产工作流界面 MVP

版本：v0.4  
日期：2026-08-18

## 1. 目标

把现有本地批处理能力组织成一条可审核、可追溯、可批量操作的资产生产线，并为后续嵌入电影数据库网站预留稳定的数据与接口边界。

本版不是最终资产库，而是生产工作台：负责从电影静帧进入、2D设计图审核、3D生成、3D审核到下载/待入库的过程管理。

## 2. 当前页面结构

- 工作流导航：全部资产、2D待审核、待生成3D、3D生成中、3D待审核、审核通过、已驳回；
- 总览：资产总数、待处理数量、已生成3D数量、已审核通过数量；
- 阶段化批量操作：来源静帧启动2D优化，2D/3D审核页批量通过或驳回，待生成3D页选择规格并批量生成，驳回页重新提交审核；
- 查询与显示：名称/标签/ID筛选，按名称或生成时间排序，图片/列表视图切换，图片模式支持三档缩略图；
- 资产卡片：稳定资产ID、设计图/模型预览、处理阶段、生成规格、标签、GLB下载；列表模式可双击编辑名称、标签和备注；
- 审核详情：2D与3D对照、分阶段通过/驳回、标签、备注、模型参数与积分；
- 后台任务：通过本地串行队列运行现有CLI，避免浏览器请求长时间阻塞。

## 3. 数据与索引

界面把三个现有数据源组合成资产视图：

1. `data/output/manifest.json`：静帧、2D任务与优化图；
2. `data/models/manifest-3d.json`：3D任务、JobId、GLB、预览图和积分；
3. `data/state/workflow.sqlite3`：人工审核、名称、标签、备注。

资产ID当前由2D输出图哈希生成，例如 `asset-f4c490729f2b177d`。它不依赖文件名，可作为以后与电影、镜头、静帧和资产库记录关联的外部键。

## 4. 本地 API

| 接口 | 用途 |
|---|---|
| `GET /api/workspace` | 返回汇总与资产列表 |
| `GET /api/assets/{id}/files/{kind}` | 受控读取静帧、2D图、预览图或GLB |
| `PATCH /api/assets/{id}` | 保存名称、标签、备注 |
| `POST /api/assets/{id}/review` | 更新2D或3D审核结果 |
| `POST /api/actions/review` | 批量通过、驳回或重新提交审核 |
| `POST /api/frames/upload` | 批量上传静帧 |
| `POST /api/actions/process-2d` | 启动2D批处理 |
| `POST /api/actions/generate-3d` | 为选中资产启动3D任务 |
| `GET /api/jobs/{id}` | 查询本地后台任务状态 |

生成接口必须携带显式确认值，页面也会在提交前展示预计积分。这是防止误触发计费任务的双层保护。

## 5. 融入现有电影数据库的建议

后续不要把本地文件路径直接写入网站业务表。建议新增资产生产服务，并建立以下关系：

```text
Movie → Scene → Shot → FrameSelection → AssetCandidate → AssetVersion → ModelVersion
```

- `FrameSelection` 保存影片、场次、镜头、时间码和原始静帧；
- `AssetCandidate` 使用当前稳定资产ID，保存名称、类别、标签和审核状态；
- `AssetVersion` 保存每次2D优化图及模型/提示词版本；
- `ModelVersion` 保存GLB、PBR规格、面数、生成平台、远端JobId和质检结果；
- 文件迁移到对象存储，数据库只保存文件ID/URL与校验哈希；
- 审核动作记录操作者、时间、结论和备注，形成审计日志；
- 当前本地 API 可逐步替换为网站内部服务，前端资产卡片与审核状态模型可以复用。
