# 电影静帧 AI 数字资产生产系统 PRD

> 版本：v0.1  
> 状态：已确认（范围冻结）  
> 文档日期：2026-08-17  
> 确认日期：2026-08-17  
> 当前阶段：进入技术方案与 POC 准备

## 1. 项目概述

### 1.1 项目背景

项目需要从电影数据库保存的静帧中识别具有资产价值的物品，通过即梦 AI 将物品从原始画面语境中提取出来、补全被遮挡或未完整展示的结构，并生成单个完整物品的干净背景图片。审核通过的资产图片再批量提交腾讯混元图生 3D，生成面向影视级虚拟制片的 3D 数字资产。

当前先建设一个可独立运行的小型生产系统，完成批量导入、2D 资产图生成、3D 模型生成及结果管理。后续再将其作为子模块接入现有电影数据库网站。

### 1.2 产品目标

1. 将“逐张截图、逐张修图、逐个生成模型”的人工流程改造成可批量执行、可审核、可追踪的生产流程。
2. 保证每个 3D 模型都能追溯到原始电影静帧、2D 资产图、生成参数及审核记录。
3. 支持一张静帧生成一个或多个独立资产，但每张 2D 垫图只包含一个物品。
4. 输出符合影视虚拟制片交换需求的 GLB 模型及 PBR 贴图资产。
5. 为后续并入电影数据库、建立标签体系和资产检索能力预留数据接口。

### 1.3 已确认的产品决策

| 项目 | 已确认方案 |
|---|---|
| 静帧与资产关系 | 一张静帧可对应 1～N 个核心物品资产 |
| 目标物品确定方式 | 默认由即梦理解画面并选择中间或关键的重要物品；允许操作者补充文字指令纠偏 |
| 2D 图片处理 | 即梦直接生成完整物品和干净背景，不增加额外抠图、分割或 Mask 流程 |
| 2D 结果约束 | 一图一物，主体完整、无遮挡、背景干净，可直接作为图生 3D 垫图 |
| 当前系统形态 | 先建设独立小项目，暂不直接改造现有电影数据库网站 |
| 未来集成方向 | 后续作为电影数据库网站的子模块，并继承影片、场景、时间码和标签信息 |
| 3D 使用场景 | 影视级虚拟制片与电影工业数字资产 |
| 3D 交换格式 | GLB |
| 材质体系 | PBR |
| 目标面数 | 约 100 万面；“三角面数/四边面数”的最终统计口径在技术验证阶段确定 |

## 2. 用户与角色

### 2.1 生产操作者

- 创建生产批次并上传静帧。
- 设置即梦生成要求或补充目标物品描述。
- 发起批量 2D 资产图生成。
- 查看任务进度、失败原因并重新提交。
- 将审核通过的 2D 资产批量提交混元生成 3D。
- 下载审核通过的资产。

### 2.2 2D 审核员

- 对照原始静帧和生成的资产图。
- 判断主体是否选择正确、结构是否完整、材质和造型是否忠于原图。
- 执行通过、驳回、重新生成，并填写审核意见。

### 2.3 3D 审核员

- 旋转查看模型及材质效果。
- 检查几何结构、PBR 贴图、面数、比例和 GLB 文件完整性。
- 执行通过、驳回、重新生成或标记人工精修。

### 2.4 管理员

- 管理用户、角色和权限。
- 配置即梦与混元 API。
- 配置默认提示词、重试次数、任务并发及存储策略。
- 查看任务量、成功率、平均耗时和成本统计。

> MVP 阶段允许同一用户同时承担以上角色，但系统仍需保留操作者和审核人的记录字段。

## 3. 产品范围

### 3.1 MVP 范围

- 批量上传电影静帧。
- 创建和管理处理批次。
- 调用即梦 API 生成干净背景的完整物品图。
- 支持一张静帧返回多个独立资产候选。
- 记录原图与多个资产候选之间的一对多关系。
- 2D 资产结果查看、通过、驳回和重新生成。
- 将审核通过的 2D 图片批量提交混元图生 3D。
- 查询异步任务进度、失败重试和结果转存。
- GLB、PBR 贴图和预览文件管理。
- 3D 结果基础审核。
- 按批次批量下载资产及清单文件。
- 保存完整生成链路、参数、版本和审核记录。

### 3.2 暂不纳入 MVP

- 与现有电影数据库网站直接集成。
- 自动同步电影、角色、场景和道具数据库。
- 在静帧上进行像素级抠图或分割。
- Mask 生成与管理。
- 专业 DCC 软件中的人工拓扑、绑定、UV 精修工作流。
- 自动发布到 Unreal Engine、Unity 或虚拟制片资产管理平台。
- 基于相似度的跨影片资产去重。

## 4. 端到端业务流程

### 4.1 主流程

1. 操作者创建生产批次。
2. 上传一组电影静帧，可填写或导入影片名、文件名、时间码等基础信息。
3. 操作者选择自动识别核心资产，或为部分静帧补充目标物品描述。
4. 系统为每张静帧提交即梦生成任务。
5. 即梦识别画面中的一个或多个核心物品，并为每件物品生成独立的干净背景完整视图。
6. 系统将每张返回图建立为独立资产候选，并关联同一来源静帧。
7. 2D 审核员逐个或批量审核资产候选。
8. 审核不通过的资产填写原因后重新生成；审核通过的资产进入 3D 待生成池。
9. 操作者批量选择通过的 2D 资产，提交混元图生 3D。
10. 系统排队执行、轮询或接收任务结果，并及时将 GLB、贴图和预览文件转存到本系统存储。
11. 3D 审核员检查模型质量。
12. 审核通过的模型进入可下载/待入库状态；不通过的模型重新生成或标记人工精修。

### 4.2 一张静帧多资产规则

- 默认模式为“自动判断”，由模型从画面中央、叙事焦点和视觉显著区域选择核心物品。
- 系统不假定一张静帧只有一个资产。
- 每个返回结果单独创建 `asset_id`，但共享同一个 `frame_id`。
- 每张结果图只能出现一个完整物品；多个物品拼在同一张图中视为不合格。
- 操作者可以删除不重要的候选，也可以添加文字目标后重新生成遗漏物品。
- 操作者可设置期望生成数量：自动、1 件、2 件、3 件或自定义。
- MVP 默认一次最多保留 5 个核心资产候选，超出时由操作者分次生成。

### 4.3 自动识别失败的降级流程

系统不增加抠图或分割步骤。当模型选错、遗漏或混合多个物品时，采用以下方式纠偏：

1. 操作者填写目标物品描述，例如“只提取画面中央的红色皮质扶手椅”。
2. 系统针对同一静帧创建新的 2D 生成版本。
3. 新版本保留原失败版本和审核原因，不覆盖历史记录。

## 5. 功能需求

### 5.1 批次管理

#### 功能

- 新建、命名和查看批次。
- 批量上传 JPG、JPEG、PNG 静帧。
- 显示文件数量、成功上传数量、重复文件和不支持文件。
- 支持拖拽上传和选择文件夹上传。
- 支持为整个批次设置统一提示词、期望资产数量和输出规格。
- 支持为单张静帧覆盖批次默认配置。
- 显示批次内各阶段数量：待处理、2D 处理中、待 2D 审核、3D 处理中、待 3D 审核、已完成、失败。

#### 基础元数据

- 批次名称。
- 影片名称。
- 来源文件夹。
- 静帧文件名。
- 可选时间码。
- 可选场景/镜头编号。
- 创建人和创建时间。

### 5.2 即梦 2D 资产生成

#### 默认目标

系统通过提示词要求模型：

- 判断画面中的核心重要物品。
- 分别生成每件核心物品的独立图片。
- 保留物品原始造型、年代、材质、颜色、磨损和设计语言。
- 对遮挡、裁切或未展示部分进行合理结构补全。
- 输出完整、无遮挡、居中的单个物品。
- 使用纯白或浅灰干净背景。
- 不出现人物、文字、水印、边框、环境和其他道具。
- 不生成复杂投影；允许轻微自然接触阴影。
- 默认输出正方形 2048×2048 图片。

#### 可配置项

- 自动识别或指定物品描述。
- 期望资产数量。
- 背景颜色。
- 输出尺寸。
- 结构补全强度或补充说明。
- 单张结果数量。
- 随机种子及模型版本（接口支持时）。

#### 结果管理

- 每个结果独立生成资产候选记录。
- 保存请求 ID、任务 ID、模型版本、完整提示词、提交时间和完成时间。
- 保存来源静帧、生成图片及缩略图。
- 支持同一资产多次重新生成并保留版本。
- API 返回临时链接时立即转存到本系统存储。

### 5.3 2D 审核

#### 审核界面

- 左侧显示原始静帧，右侧显示当前资产图。
- 支持放大、缩小、全屏及版本切换。
- 显示系统识别出的资产名称和候选编号。
- 显示生成参数和历史审核意见。

#### 审核动作

- 通过。
- 驳回。
- 修改资产名称或目标描述后重新生成。
- 标记重复资产。
- 删除无价值候选。
- 批量通过或批量驳回。

#### 2D 不通过原因

- 选错主体。
- 多个物品混在同一图。
- 主体结构不完整。
- 补全结构不合理。
- 造型偏离原图。
- 材质或颜色偏离原图。
- 背景不干净。
- 主体被裁切。
- 清晰度不足。
- 其他。

### 5.4 混元 3D 生成

#### 提交规则

- 只有 2D 审核通过的资产可以提交 3D。
- 支持单个提交和批量提交。
- 同一个 2D 资产可以创建多个 3D 版本。
- 系统根据服务并发能力自动排队，不因批量提交导致任务丢失。
- 支持失败重试、人工重试和取消尚未开始的任务。

#### 目标输出

- 主交换文件：GLB。
- 目标几何复杂度：约 100 万面。
- PBR 材质体系至少关注：Base Color、Normal、Roughness、Metallic。
- 可选保留 AO、Displacement/Height、Opacity 等接口实际返回的贴图。
- 保存模型预览图、原始接口结果和贴图文件包。
- GLB 中应正确绑定材质和纹理；同时保留独立贴图文件便于后续精修。

#### 文件保存要求

- 任务完成后立即下载并转存模型，不长期依赖服务商临时 URL。
- 保存文件大小、面数、顶点数、材质数量和贴图清单。
- 文件下载失败与模型生成失败分别记录，支持单独补拉文件。

### 5.5 3D 审核

#### 审核界面

- 浏览器内 GLB 旋转、缩放和平移预览。
- 支持基础光照环境切换。
- 支持材质模式、无材质模式和线框模式。
- 显示面数、顶点数、材质数、贴图数量和文件大小。
- 对照显示原始静帧和审核通过的 2D 垫图。
- 支持查看不同 3D 版本。

#### 3D 审核动作

- 通过并标记可入库。
- 驳回并重新生成。
- 标记“需要人工精修”。
- 标记“仅概念资产，不满足影视级标准”。
- 批量通过或批量下载。

#### 3D 不通过原因

- 几何结构错误。
- 缺失或多余结构。
- 轮廓与参考图不符。
- 模型穿插或破面。
- 面数不符合要求。
- UV 或贴图错误。
- PBR 材质不完整。
- 颜色或材质偏离参考图。
- GLB 无法打开或文件损坏。
- 其他。

### 5.6 下载与交付

- 支持下载单个资产。
- 支持按批次下载全部审核通过的资产。
- 每个资产包至少包含 GLB、PBR 贴图、2D 垫图和元数据清单。
- 支持生成 CSV/JSON 总清单。
- 下载包中保留稳定资产编号，避免依赖中文文件名匹配。

建议目录结构：

```text
batch_<batch_id>/
  manifest.csv
  manifest.json
  assets/
    <asset_id>/
      source_frame/
      reference_2d/
      model/
        <asset_id>.glb
      textures/
      previews/
      metadata.json
```

### 5.7 任务中心

- 查看所有 2D 和 3D 异步任务。
- 按批次、任务类型、状态、提交人和时间筛选。
- 显示排队、执行、成功、失败和重试状态。
- 显示服务商请求 ID 和可读失败原因。
- 支持失败任务批量重试。
- 支持设置最大重试次数和退避时间。
- 对鉴权失败、额度不足、内容审核失败、限流和下载失败进行分类。
- 不对明确不可重试错误进行无限重试。

### 5.8 资产索引与未来网站集成预留

当前独立系统仍需提前保存以下字段：

- `asset_id`：系统永久资产 ID。
- `frame_id`：来源静帧 ID。
- `batch_id`：生产批次 ID。
- `source_system`：来源系统，当前可为 `standalone`，未来可为电影数据库网站标识。
- `source_record_id`：未来电影数据库中的记录 ID。
- 影片、集数、场景、镜头、时间码。
- 资产中文名、英文名、别名。
- 分类、材质、颜色、年代、风格、用途。
- 关联角色、关联场景和配套资产。
- 来源静帧、2D 版本、3D 版本和审核状态。
- 即梦与混元模型版本、提示词和参数。

MVP 只要求录入和保存基础字段，不要求完成复杂搜索体验；但数据结构不能只靠文件夹名称维持关系。

## 7. 核心状态设计

### 7.1 静帧状态

```text
已上传 → 待生成2D → 2D生成中 → 已产生资产候选
                         └→ 生成失败 → 待重试
```

一张静帧产生资产候选后仍可继续补充生成，不因已有结果而关闭。

### 7.2 2D 资产状态

```text
候选已生成 → 待2D审核 → 2D已通过 → 待生成3D
                 ├→ 2D已驳回 → 重新生成中
                 ├→ 已删除
                 └→ 标记重复
```

### 7.3 3D 模型状态

```text
待提交 → 排队中 → 生成中 → 文件转存中 → 待3D审核 → 已通过/可入库
             ├→ 生成失败 → 待重试
             ├→ 转存失败 → 待补拉
             └→ 3D已驳回 → 重新生成/人工精修
```

## 8. 核心数据对象

| 数据对象 | 用途 | 关键关系 |
|---|---|---|
| Batch | 一次批量生产任务 | 一个 Batch 包含多个 Frame |
| Frame | 原始电影静帧 | 一个 Frame 可产生多个 Asset |
| Asset | 独立的物品资产身份 | 一个 Asset 关联一个来源 Frame，可有多个 2D/3D 版本 |
| ImageVersion | 即梦生成的 2D 资产图版本 | 属于一个 Asset |
| ModelVersion | 混元生成的 3D 模型版本 | 来源于一个已通过的 ImageVersion |
| GenerationJob | 外部 API 异步任务 | 关联 2D 或 3D 版本 |
| Review | 审核记录 | 关联版本、审核人、结论和原因 |
| FileObject | 图片、模型、贴图、预览等文件 | 关联 Frame、ImageVersion 或 ModelVersion |
| Tag | 分类与检索标签 | 可关联 Asset |

## 9. 权限原则

- 生产操作者可以创建批次和提交任务，但不能修改他人的审核结论。
- 审核员可以审核并填写意见。
- 管理员可以配置 API、提示词和系统规则。
- 所有通过、驳回、删除和重新生成操作保留操作日志。
- API 密钥不在页面、任务日志或下载清单中明文显示。

## 10. 非功能需求

### 10.1 稳定性

- 系统重启后未完成任务可以恢复查询。
- 外部 API 超时不会导致批次整体失败。
- 同一任务重复回调或重复查询不会创建重复资产。
- 临时下载链接过期前必须完成转存。

### 10.2 可追溯性

- 任意 GLB 都能追溯至对应资产、2D 垫图和原始静帧。
- 任意重新生成都创建新版本，不覆盖已审核历史。
- 保留服务商任务 ID、请求 ID、模型版本和参数。

### 10.3 批量能力

- MVP 目标支持单批次至少 100 张静帧。
- 批量提交由后台队列执行，用户可关闭页面后继续处理。
- 并发数由管理员配置，并遵守外部 API 限制。

### 10.4 文件与安全

- 图片、模型和贴图存储在受控文件存储或对象存储中。
- API 密钥只保存在服务端环境变量或密钥系统中。
- 下载地址设置合理有效期和访问权限。

## 11. MVP 验收标准

### 11.1 业务验收

1. 用户可一次上传至少 100 张静帧并创建批次。
2. 系统可为每张静帧提交即梦任务，并展示实时或轮询状态。
3. 一张静帧可以保存多个独立资产候选，每个候选拥有不同 `asset_id`。
4. 2D 结果可以通过、驳回和带目标描述重新生成。
5. 审核通过的 2D 资产可以批量提交混元图生 3D。
6. 系统能够在混元任务完成后自动转存 GLB 和相关文件。
7. 3D 模型可以在浏览器中预览、审核和下载。
8. 下载包中的 GLB、PBR 贴图、2D 垫图和清单能够通过同一 `asset_id` 匹配。
9. 任意失败任务可查看原因，并可按规则重新执行。
10. 系统重启后，未完成任务不会丢失。

### 11.2 2D 质量验收

- 每张图仅包含一个核心物品。
- 主体完整、未被画面边缘裁切。
- 背景为纯白或浅灰，且没有人物、文字和其他物品。
- 物品的核心轮廓、颜色、材质和年代特征与静帧一致。
- 遮挡区域的补全符合物品结构常识。
- 清晰度满足后续混元图生 3D 输入需要。

### 11.3 3D 质量验收

- GLB 文件可正常加载和交换。
- 模型大体轮廓和关键结构与 2D 参考图一致。
- 目标面数接近约 100 万面，允许范围在 POC 后冻结。
- PBR 材质可正确显示，必需贴图无缺失和错链。
- 模型不存在明显破面、严重穿插、极端拉伸或悬浮碎片。
- 模型、贴图、预览和元数据文件能够完整打包下载。

## 12. 关键指标

- 静帧上传成功率。
- 即梦任务成功率与平均耗时。
- 每张静帧平均资产候选数量。
- 2D 首次审核通过率。
- 2D 平均重新生成次数。
- 混元任务成功率与平均耗时。
- 3D 首次审核通过率。
- 单个审核通过资产的平均 API 成本。
- 临时文件转存成功率。
- 从静帧上传到 3D 可下载的平均生产周期。

## 13. 分阶段实施建议

### 阶段 0：样本 POC

- 选择 20～50 张代表性静帧。
- 验证即梦能否稳定执行“一张静帧识别多个核心物品、每件物品单独出图”。
- 验证提示词、输出分辨率和背景规则。
- 验证单张 2D 垫图生成约 100 万面 GLB/PBR 资产的实际质量。
- 记录成本、耗时、失败率和审核通过率。
- 根据结果冻结 MVP 的默认提示词和 3D 验收范围。

### 阶段 1：2D 批处理 MVP

- 批次、上传、即梦任务、2D 审核、版本和文件转存。

### 阶段 2：3D 批处理

- 混元任务队列、GLB/PBR 转存、3D 在线预览和审核。

### 阶段 3：资产库与网站集成

- 标签、搜索、配套关系、正式入库。
- 通过 `source_system` 和 `source_record_id` 对接现有电影数据库网站。

## 14. 风险与验证项

### 14.1 一次调用自动拆分多个资产的稳定性

即梦能理解多个重要物品并不等于每次都能稳定返回“一件物品一张图”。必须通过 POC 验证：

- 是否会把多个物品拼在一张图中。
- 是否会遗漏画面边缘但重要的资产。
- 多张返回图能否稳定对应不同物品。
- 相同提示词下结果数量是否稳定。

如果稳定性不足，产品降级方案是“同一静帧按不同文字目标多次调用”，仍不增加抠图或分割流程。

### 14.2 影视级质量与生成式 3D 能力边界

约 100 万面不等于影视级可用。验收还需关注轮廓、拓扑、UV、PBR、尺度、结构正确性和后续可编辑性。POC 需要区分：

- 可直接用于远景/中景虚拟制片的资产。
- 需要人工精修后使用的资产。
- 仅能作为概念或占位模型的资产。

### 14.3 临时链接和任务有效期

外部服务返回的任务和文件链接可能存在有效期。系统必须保存任务信息并尽快转存实际文件，不能把服务商 URL 当作永久资产地址。

### 14.4 影片素材与内容审核

电影静帧可能触发版权词、人物或内容安全审核。POC 应记录审核失败样本，并确保使用的影片素材具备合法生产和处理权限。
